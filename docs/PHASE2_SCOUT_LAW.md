## 1. What Phase 2 is

Phase 2 is **the first scouting prompt** — the exhaustive scout mission already
written inside gold #2 (`docs/REASONING_KERNEL.md`):

- Extract every formula
- Extract every rule
- Extract exact workflows
- Extract approval matrices
- Detect conflicts
- Create domain constitutions
- Certify each domain pack

It is a **factory development mission, executed by Kimi Code once per domain**
against our donor repositories (The_Fork, RetailOpsReference, Projectfifteen,
Projecttwo, Projectten, projectseven, Cerebrum-BuildOps).

## 2. What triggers for paid subscribers

**The subscription never launches a scout.** The scout is a fixed factory cost
paid once per domain, not a per-subscriber event.

What unlocks for paid subscribers is the scout's **certified output**:

```text
domain_approved packs + private organisation intelligence
        ↑ produced once by the Phase 2 scout
        ↑ unlocked per subscriber by require_entitled (402 gate)
```

Paid subscribers consume certified intelligence; they do not trigger scouting.

## 3. The enrichment law (the Founder's words, ratified)

> **Phase 2 enriches the system. It does not redesign Phase 1.**

- The scout is **read-only** on donor product repositories.
- The scout never modifies the v0.1 Standard Control Layer, the Universal
  Kernel, or any Phase 1 contract.
- Packs deepen (`candidate → domain_approved`); contracts stay stable.
- A certified pack must install into a Phase 1 product with **zero changes**
  to the product's generated code — enrichment is data and certification,
  never redesign.

## 4. The two extractions — never conflate them

| | Donor scout | Customer-org extraction |
|---|---|---|
| What | Phase 2 mission on OUR donor products | Learning a CUSTOMER's own documents, CoA, policies, procedures |
| Runs | Once per domain, by the factory | Per paid subscriber, inside their tenant |
| Output | Certified `domain_approved` domain packs | Private Layer-2 RAG + customer-specific reasoning context |
| Gated by | Nothing (factory cost) | `require_entitled` — Pro/Team only |

## 5. What must never happen

- A subscription event triggering an exhaustive scout run
- The scout modifying, rewriting or "improving" Phase 1 machinery
- Customer-org extraction leaking into the shared domain pack — customer
  intelligence stays inside the customer's tenant, always
- Uncertified (`candidate`) output sold as certified — the honesty-label law
