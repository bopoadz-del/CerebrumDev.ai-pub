# 2026-09-11 — chromadb 1.5.9 (Linux pip-audit resolve)

**Date:** 2026-09-11
**Package:** `chromadb==1.5.9` (latest published on this date; pin in
`backend/requirements.txt`)
**Decision:** `accept_until_fix` for each id below
**Constraint source:** the package itself. PyPI `chromadb 1.5.9`
`requires_dist` has no newer chromadb extra that ships a patched server,
and `pip-audit` reports `fix_versions: []` for every id. `pip index
versions chromadb` lists `1.5.9` as latest.

These four advisories (five scanner rows: `PYSEC-2026-311` is emitted
twice from two feeds) are the remaining Linux resolve after
`python-multipart` was upgraded. They all describe the **Chroma HTTP
API**, not the embedded `PersistentClient` this factory uses.

Factory call sites (the twin greps these):

- `backend/app/core/chroma_store.py` — `chromadb.PersistentClient(path=…)`
- `backend/app/core/packager.py` — same
- `backend/app/core/platform_packager.py` — same

No `HttpClient`, no `chroma run`, no mounted `/api/v2/tenants` server.

Revisit: the day `pip-audit` prints a non-empty `fix_versions` for any
id below, this note is stale. Upgrade the pin or rewrite the note. Do
not add `--ignore-vuln`.

---

## PYSEC-2026-311

- **Aliases:** CVE-2026-45829, GHSA-f4j7-r4q5-qw2c
- **Scanner:** pre-auth code injection on
  `/api/v2/tenants/{tenant}/databases/{db}/collections` via a malicious
  model repository with `trust_remote_code=true`. Affects 1.0.0 or later.
- **Declared / observed:** no fixed release. Factory never starts that
  HTTP endpoint and never passes `trust_remote_code`.
- **Decision:** accept until a fixed chromadb exists.

## PYSEC-2026-3813

- **Aliases:** CVE-2026-45830, GHSA-2wm9-hf6c-p5cr
- **Scanner:** missing authorization on 0.4.17+ lets any authenticated
  HTTP user read/write/update/delete any tenant's collection.
- **Declared / observed:** no fixed release. Factory process-local
  `PersistentClient` has no multi-tenant HTTP auth surface.
- **Decision:** accept until a fixed chromadb exists.

## PYSEC-2026-3814

- **Aliases:** CVE-2026-45833, GHSA-36p7-vc44-83pf
- **Scanner:** authenticated code injection on
  `/api/v2/tenants/default_tenant/databases/default_database/collections/{collection_id}`
  if the caller has `UPDATE_COLLECTION`, via a malicious model repository
  and `trust_remote_code=true`. Affects 0.4.17 or later.
- **Declared / observed:** no fixed release. Same embedded-client
  posture as 311.
- **Decision:** accept until a fixed chromadb exists.

## PYSEC-2026-3815

- **Aliases:** CVE-2026-45831, GHSA-xph7-9rjv-w5fr
- **Scanner:** `SimpleRBACAuthorizationProvider` (0.5.0+) checks that a
  user holds a permission but not which tenant/database/collection it
  applies to.
- **Declared / observed:** no fixed release. Factory does not enable
  Chroma RBAC or the HTTP authorization provider.
- **Decision:** accept until a fixed chromadb exists.
